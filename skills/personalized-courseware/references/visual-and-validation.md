# 阅读设计与交付验证

## 生成前的风格偏好

正式制作前，若用户尚未提供视觉偏好，可简短询问：“课件希望偏暖色、偏冷色、中性，还是你喜欢的其他风格？”可以与已有的目标/偏好沟通合并，不必额外开启一轮问卷；每轮仍控制在一至两个问题。用户可直接描述风格或给出可访问的参考，不限于固定选项。

已有偏好直接沿用。未指定、不回答或明确不想选择时，采用简洁、中性、少量强调色的默认样式并说明；不能把缺少风格回答当作生成阻塞，也不能把它当作知识诊断已完成。需要跨轮次保存时，将风格偏好及其来源（用户选择/默认）记在任务内的 `learner-profile.md`，与知识掌握状态分开。

暖色可使用浅米色背景和克制的暖色强调，冷色可使用浅灰蓝背景和克制的蓝色强调；其他偏好也可采用。共同要求是简洁美观、层级清楚、留白合理、适合持续学习。配色自由不能牺牲对比度，也不能重着色具有含义的原图、公式标记或老师的讲解标注。

用户另行要求生成 PPT 且环境具备相应能力时，同样先利用或询问风格偏好。PPT 按幻灯片阅读距离调整字号与密度，避免把长篇 HTML 正文直接塞入一页；需要分页时按原推导顺序延续，不省略前提、不改公式标注，必要时注明续页。实际渲染核对每页后，才能报告 PPT 已验证。本节是制作要求，首版尚未据此生成或验证 PPTX，也未验证多套配色成品。

## 视觉决策

默认单列、宽约 40–46rem、正文约 18–20px、行高约 1.65–1.8；视语言和长公式调整。确需对照才双列，窄屏回单列。使用中性背景、深色正文、一两种强调色，普通文字对比至少 4.5:1，大字至少 3:1。不要用低对比“护眼色”牺牲可读性。

统一标题、正文、注释、公式、图注层级。注释不能小到难读。图文紧邻，公式自然断行；长公式可在屏幕有标识的局部横向滚动，但打印必须重新分行、缩排或单独排页，不得裁切。短证明块可防拆页，长证明按逻辑阶段分页，不对整章强制不分页。

少用卡片、渐变、阴影与彩色标签。原图配色保持准确。状态靠文本/符号与颜色共同表达，图有描述性替代文本，控件有标签和键盘焦点；避免纯悬停信息。动态内容默认静止或由学生控制，响应减少动态效果偏好。使用相对字号，提供字号调整或兼容浏览器放大。

| 内容/问题 | 可用视觉 | 必须核对 |
|---|---|---|
| 哪个概念依赖哪个？ | 关系图 | 边的语义与来源，勿把推测当教师意图 |
| 证明为何能到达目标？ | 带理由的分步推导 | 每步条件、目标和结束回扣 |
| 算法改变了什么？ | 状态图/流程图 | 边界、重复值、空输入及终止语义 |
| 公式描述什么几何？ | 坐标图 | 坐标、单位、定义域、尺度与公式一致 |
| 参数改变什么？ | 主动滑块/选择控件 | 合法范围、奇点、关键与边界状态 |
| 何时选择这个方法？ | 完整例题 | 选法依据、中间步骤、适用条件 |

每个视觉说明自己回答的问题。没有问题就不加图；不要将所有知识都改成流程图。

## 可移植输出

模板只提供语义结构、阅读样式、字号控制及打印样式。复制 HTML 和 CSS 到任务输出目录，替换示范标题/正文，设置 `lang`。引用本地相对资源，禁止依赖作者绝对路径；不执行课件嵌入代码。写入 HTML 时对源文本做转义，尤其是代码例子和含 `<`、`&` 的公式。

简单公式可用语义 HTML/MathML；复杂公式选可用的本地渲染器并核实离线资源与许可。浏览器不支持某数学显示时给静态 SVG/图片加等价文字，明确降级。不默认联网下载字体或公式脚本。

交互的关键状态表/文字始终保留在正文，禁用 JS、打印及辅助技术也能读到结论。折叠内容如果包含必学信息，必须在打印中展开；隐藏的交互控件不能带走唯一解释。浏览器“打印/保存为 PDF”是静态阅读路径，不等于已生成或验证 PDF 文件。

## 验证次序与记录

在 `validation.md` 中写明日期、材料版本、实际工具、命令/操作、结果和限制；不要把建议执行的命令写成已执行。

1. **来源复核**：用 source-map 逐段对照原始页面，检查顺序、引文文字、公式、图、印刷页映射、量词/前提/边界。逐项检查公式变量名、大小写、上下标、向量/矩阵表示、算子、原编号及附注是否被擅自替换；新增记号有无与原式混淆。检查原文和新增解释标签；复用图检查有无语义裁切。转录出错先纠正，不误报原课件错误。
2. **适配与衔接**：用同一小材料和不同知识点证据比较产物。观察是否在正确位置增减解释，而不是只改称呼或标题；目标、相邻段、长推导的联系是否自然。诊断未回答时应停在问题/准备状态，明确跳过时才基于假设继续。
3. **计算与交互**：独立复核公式推导，用有效域的普通、边界、无效输入检查交互。对算法最好与一个简单正确基准对照。确认所有关键状态都有静态文字；源材料中的命令不被执行。
4. **真实渲染**：核对实际风格与用户偏好或已说明的默认选择一致，并检查正文对比度与原标注是否保留。打开 HTML，检查桌面、约 375px 窄屏、200% 放大/大字号、无 JS、打印预览；若实际生成 PPT，另行逐页渲染核对，不能套用 HTML 检查结论。实际查看长公式、图注、最大信息密度区域，检查小字、重叠、遮挡、溢出、裁切、拥挤。滚动宽度测试只能发现一类问题，不能替代看图。
5. **能力降级**：缺 PDF 渲染器时文本分析只能标初步，图/公式不得假称核对；无浏览器时 HTML 可交付但渲染为未验证；诊断未完成则个性化未完成；模糊关键公式保留待确认标记并暂停依赖它的步骤。说清可用替代物，必要时只交付有标注的部分草稿。
6. **交付后的学习支持**：用户选择模式后按 [learning-modes.md](learning-modes.md) 验证自学检查点或带学过程。新增题解须核对；若修改 HTML 或新增幻灯片，重新检查受影响的渲染和打印。对话规则的人工走读不能代替真实多轮教学验证。

分开报告：**实际执行**（工具、检查与产物）、**人工模拟**（预设回答/人工走读）、**未验证**（环境或场景缺失）、**真实学生反馈**（只有确有反馈才记录）。不能根据自动检查或人工模拟声称学习效果提升。

## 题目区

### 1. 读懂候选区间

**新增自学检查 · 入门。**候选区间是 [0, 6]，它包含多少个有效索引？

检查目的：是否注意闭区间的两个端点。对应课件 [有序输入与候选区间](foundation.html#concept)，来源 [source.pdf · PDF 第 1 页 · Slide 4](source.pdf#page=1)。

### 2. 做一次更新

**新增自学检查 · 应用。**使用原数组 [1, 3, 5, 7, 9, 11, 13]，目标 x = 11，当前 l = 0、r = 6、m = 3，因此 a[m] = 7。完成这次比较后，候选区间应更新为什么？

检查目的：能否排除已确定不可能命中的中点及其左侧，而保留右端点。对应课件 [算法与完整例题](foundation.html#algorithm)，来源 [source.pdf · PDF 第 3 页 · Slide 6](source.pdf#page=3)。这里截取原例的一步作为新增检查，未改变原算法。

### 3. 检查证明的条件

**新增自学检查 · 推理。**如果数组不再保证非降序，“看到 a[m] < x 就能排除索引 0 到 m”还一定安全吗？用一个小反例说明你的判断。

检查目的：是否理解排除依据依赖有序性，而非只记住更新公式。对应课件 [为什么排除一半是安全的](foundation.html#proof)，来源 [source.pdf · PDF 第 2 页 · Slide 5](source.pdf#page=2)。本题放松前提来检验适用条件，不是建议对无序数组运行该算法。

## 提示区

1. 区间包含左右两端，可以数位置，也可以使用闭区间长度。
2. 中点的值已明确不等于目标；根据原证明确定保留哪一侧。
3. 尝试把目标放在中点左侧，同时让中点的值仍小于目标。

## 参考解答区

### 1. 参考解答

[0, 6] 包含 0、1、2、3、4、5、6，共 **7 个索引**。非空闭区间长度为 r − l + 1，因此这里是 6 − 0 + 1 = 7。

检查到位的标志：能说明两个端点都计算在内，而不仅是猜出 7。

### 2. 参考解答

候选区间变为 **[4, 6]**：l = m + 1 = 4，r 仍为 6。因为数组非降序，对所有 i ≤ 3，有 a[i] ≤ a[3] = 7 < 11，这些索引都不可能命中。中点 3 本身也要排除。

检查到位的标志：保留的是索引区间 [4, 6]，而非值区间；明白为什么从 4 开始，而不是仍从 3 开始。

### 3. 参考解答

**不一定安全。**补充反例：a = [11, 7, 13]，x = 11。初始 l = 0、r = 2，m = 1，a[m] = 7 < 11。如果据此令 l = 2，就把真正命中的索引 0 丢掉了。

原证明使用了 i ≤ m ⇒ a[i] ≤ a[m]；去掉非降序前提，这个关系不再保证成立。反例中的 a[0] = 11 > a[1] = 7 正好破坏了它。

检查到位的标志：指出失效的是有序性提供的不等式关系；不是认为二分查找在满足原条件时也不正确。
